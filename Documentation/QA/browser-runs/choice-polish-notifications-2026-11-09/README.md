## Additional actual-sync finding

However the actual `syncUserGym` path then aborted: `Gym connection changed during sync`. Its captured revision predates the successful renewal, which deliberately increments that revision. The new real-adapter full-sync regression records **5/7** before this correction and **7/7** after. The sync now discards the interrupted snapshot and rereads once with the current active connection. It keeps the write fence, does not retry unavailable/throttled connections, and stops after one restart when revisions keep changing. No booking, cancellation or purchase is repeated: all these paths are reads.

`notification-after-initial-sync-failure.txt` preserves this finding. Aarmy was left healthy with its freshly renewed session, without an incident or notification at that point. A second experiment deployment will include this worker correction before the final definitive-expiry test.
