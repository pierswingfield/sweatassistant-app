# Standing MCP egress candidate — not activated

This replaces the temporary acceptance lease for general MCP transport (reads first; action writes separately gated). It is not an elapsed-time/user-attempt pilot architecture. Current runtime remains provider reads off, profile-only true and old read-window opt-in unset. No service, network, Cloudflare rule or live gym data changed in this slice.

## Boundary and budgets

Both adapters use the shared `logger.providerFetch` transport. When `MCP_STANDING_EGRESS_ENABLED=true`, only an active MCP execution uses the private broker. Normal native PWA/scheduler work retains existing common admission lanes/reservations. Stage native authentication/profile bootstrap still uses the unchanged legacy restricted gateway; stage scheduler/poller/calendar/history suppression remains tied to the existing profile-only flag. The app stays solely on its internal bridge. It must never join the broker's outbound bridge.

The broker receives a dedicated random receipt key, mounted as one read-only mode0600 file; **never** mount the app config directory, DB, OAuth keys, encryption/JWT keys or gym credentials into it. A separate mode0700 directory holds its mode0600 SQLite replay ledger. The key file must contain43–128 base64url/hex-compatible characters and differ from app JWT/encryption secrets. Generate and write it privately after review, without printing it. Retain state across container restart; it contains nonce hashes/expiry and opaque action replay identifiers/timestamps, not raw account data or credentials.

A receipt is signed inside the already-admitted app transport callback, after both durable MCP and shared provider admission. It binds opaque account identity, gym, tool/scope, canonical URL/query, method, headers/credential, exact body, nonce and issuance time. Signer checks current grant and linked session; caller headers cannot supply actor context. Broker accepts receipts for15seconds with at most5seconds future skew, commits single-use nonce intent with SQLite FULL sync before forwarding, and never follows redirects. Separate broker state rejects accidentally supplied app databases.

The existing app budget remains authoritative: one MCP execution/user across gyms;60 HTTP requests/min/account,40/min/client/grant,1000/day/account; provider12/min/account/gym,200/day/account,30/min/gym,60/min/fleet and six attempts/tool. Shared native/scheduler reservations remain additionally enforced. No second independent gateway quota is introduced. Broker permits one in-flight account hop across gyms; different accounts remain independent. Its durable nonce table is bounded to10000 live entries/60seconds retention. Request16KiB, response4MiB and ten-second whole-hop deadline bound parsing/upstream/body work. App envelope consumption is bounded to6MiB. No provider URLs, queries, headers, bodies, receipts or secrets are logged by the broker.

Provider protocol policy lives under `server/providers/egress-policy.js`. It derives hosts/base paths from the gym registry and rejects unknown providers, encoded paths, noncanonical/duplicate/unsupported queries, historical collections, unapproved mutations and unauthorized headers. Current sources cover CodexFit v2 ranged events (seven-day chunks), v1 details/studios/profile/heartbeat/bookings, and MarianaTek bounded classes/details/upcoming reservations/credit inventory. Query pages are at most6 and dates at most14 days. The four provider read tools and bounded preflight/reconciliation reads for the five guarded action tools are supported. Action receipts additionally bind opaque grant/client identifiers, all three required scopes, action ID/operation/input/resolved class, credential digest and body digest. They are minted after current authorization; mutating receipts additionally require the app's FULL-synchronized submission intent and final executing-state check. Independent `MCP_EGRESS_WRITES_ENABLED` must be true in **both** app and broker; it defaults false and the source Compose/environment keep it false. `MCP_WRITES_ENABLED`, provider activation, OAuth scope, user preference and per-action first-party approval are still required.

Exact mutation contracts are CodexFit v1 POST bookings (one event/slot), DELETE booking, v2 PATCH booking (one slot); MarianaTek POST personal standard reservation (existing credit/membership payment option), cancel and in-place swap. No card/payment/history/auth route is admitted. Guarded no-seat CodexFit resolution makes only one POST attempt; native fallback behavior is unchanged. Action credential renewal and cancel/rebook fallback are prohibited. Broker commits an opaque action identifier before dispatch; it rejects another mutation for that action even with a fresh nonce or after restart. Records are retained indefinitely, capped at100000; capacity fails closed and must not be cleared to retry uncertainty. Same-action successful detail/payment reads alone may be reused for five seconds (six entries, at most four MiB per response), with current authorization/session rechecks; reservation snapshots are never memoized. The executing shared mutation may reuse its own positively complete preflight snapshot for at most five seconds, after checking current action authorization/session; neither approval-time snapshots nor reconciliation are reused. The account/gym minute allowance is12 attempts so normal cold preparation and execution fit without waiting/reapproval; the six-attempt tool ceiling,200/day/account,30/min/gym and60/min/fleet remain unchanged. Cache hits consume no provider attempt. Native credential/bootstrap routes are not broadened.

## Anonymous abuse and trusted addresses

Protection defaults **on** when MCP is enabled; `MCP_ABUSE_PROTECTION_ENABLED=false` is an operator override, not a user preference.20 anonymous auth failures/60seconds trigger a five-minute ban; repeat bans grow exponentially to one hour. Hashed IP state and failed-token cache each cap at4096 entries, with bounded expiry. Failed-token caching does not cache dynamic account-policy denials. Valid authenticated users are verified and governed by account budgets even when sharing a banned hosted-client IP. Discovery remains available; no browser challenge is introduced.

`MCP_TRUSTED_PROXY_IPS` must contain only independently verified exact immediate proxy IP literals. CF-Connecting-IP is accepted only from those socket peers and only as a single valid IP. X-Forwarded-For never supplies this identity. Empty configuration uses the socket peer; do not populate a whole bridge/subnet or trust arbitrary request headers. Pin/verify the tunnel's origin peer and preserve the closed app network before rollout.
