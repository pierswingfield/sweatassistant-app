## Cloudflare launch policy

1. **DNS/tunnel:** check zone account ownership against the tunnel account, nameserver delegation and all record pages; add only explicit apex/app/(optional www) CNAMEs, proxied, no public Oracle A/AAAA. Verify CAA and no name conflicts at execution time. Preserve unrelated ingress entries and catch-all; tunnel config PUT replaces the whole configuration, so export and compare before/after. Test public IPv4 and IPv6 edge reachability where available.
2. **Certificates/TLS:** verify Universal SSL issuance and certificate SANs for apex/app/(www), expiry, hostname validation and full chain before enabling redirects. Universal SSL covers apex plus first-level subdomains, normally issued within 15 minutes–24 hours of activation; an active zone is not the acceptance test. Set minimum TLS 1.2 and HTTPS redirect on the new zone after compatible-client checks. No HSTS preload; settle the apex includeSubDomains issue above first. DNSSEC enablement is useful but a separate small change after DNS is stable; it is currently disabled. [Universal SSL](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/enable-universal-ssl/).
3. **Origin encryption:** retain the working HTTP Docker ingress behind the tunnel unless separately redesigning transport. Edge-to-cloudflared uses the tunnel; the final local Docker HTTP hop is not TLS. Do not order/install an origin certificate solely because the website domain changes, or switch to Flexible to make an error disappear. Record the final zone mode and verify end-to-end public TLS; Full/strict terminology does not itself prove that local HTTP hop is encrypted. [Tunnel architecture](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/).
4. **Protection:** inventory effective managed WAF, custom rules, rate limits, Bot settings, BIC, Access, redirects, Workers, transform and cache rules before applying a reviewed hostname-scoped equivalent. Preserve the intent of existing Brotli-body and crawler blocks after checking applicability; do not copy unrelated wingfield services' rules. Preserve app login/invite/feed/analytics rate limits. Keep the public app/landing outside an Access login wall; app/admin authentication still applies. New-zone lack of matching Access rules is **not** proof of a universal exemption from account controls.
5. **Machine/browser subrequests:** avoid interstitial challenges on token ICS, API/SSE, worker/manifest/assets and analytics responses. If BIC causes incompatibility, use a narrowly scoped supported Skip rule for that product/host/path; keep unrelated WAF checks. Free Bot Fight Mode is currently off: do not enable it and assume a WAF exclusion will work. It cannot be skipped using custom rules. Do not trust a User-Agent string as authentication. [Challenge response compatibility](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/), [supported Skip options](https://developers.cloudflare.com/waf/custom-rules/skip/options/), [Bot Fight limits](https://developers.cloudflare.com/bots/get-started/bot-fight-mode/).
6. **Cache/transform:** explicitly bypass shared cache for `/api/*` (including ICS), admin/auth/private HTML, `/_a/*`, `/sw.js` and `/manifest.json`; avoid stale app navigation shells. Respect origin revalidation for public HTML and long cache only for genuinely versioned immutable assets. Do not give unversioned icons/mascot arbitrary permanent TTLs. Inspect Browser Cache TTL, Edge Cache TTL, Cache Everything/Page Rules, Cache Rules, Workers and header transforms to locate the observed four-hour worker rewrite; fix only its actual owner. Disable script rewriting/injection/optimization for app worker/modules if enabled and incompatible. Prove public response headers/body hash match the intended origin and updates propagate. `no-cache` permits storage with revalidation; it does not mean `no-store`. [Cache directives and overrides](https://developers.cloudflare.com/cache/concepts/cache-control/).

## Rollback and retirement

Before cutover, record the current immutable production image/release, production environment backup, DB backup, full tunnel config and changed zone rules/DNS. Keep secret backups outside the repo. Rollback triggers include wrong upstream, invalid TLS, login/invite failure, missing calendar events/changed UIDs, broken PWA install/push or stale worker, and unhealthy automation.

On rollback, remove/disable new redirects first, restore the old public host/config and previous image if needed, and restore only the specifically changed Cloudflare records/rules/ingress from the captured baseline. Do not restore the DB merely to reverse a hostname change: preserve any valid writes made during the attempt, and use data restore only for demonstrated corruption under a separate recovery decision. Keep the stable UID namespace fixed during rollback too. Permanent cached redirects and HSTS cannot be instantly recalled, which is why they come last.

After successful acceptance and the agreed short overlap, make old landing/browser redirects permanent and document the owner's reinstall/re-subscribe steps. Retire old calendar routes only after their use is explicitly settled; keep the old hostname/certificate while any retained feed depends on it.
